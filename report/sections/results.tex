\section{Model selection}
We selected the best model by picking the one which gives the best VSD validation score, we then compute all the other metrics based on this model. 
To retrieve an accurate list of recommended items to calculate the VSD we perform the following operations:
\begin{enumerate}
    \item Retrieve the user's tracks sorted by their affinity
    \item Perform recommendation with the model (NN, LMF or VAE), retrieving the items list with a predicted affinity (which is the distance for the NN)
    \item We sort recommendations list by the score we got
    \item We remove the first $N=25$ items of ground truth from the recommendations
    \item We calculate the the similarity score of the first $N=25$ items of the sorted ground truth and the top $N=25$ items of the recommendation
\end{enumerate}

\section{NN vs NN Full}
As part of the data ablation analysis we separated our Nearest Model fitted only on the train set and the same model fitted with the full dataset including the train set, the validation and the test set. This allows us to determine if we get better results by adding more data in the Nearest Neighbors space or not.

\section{Best Nearest Neighbor hyper-parameters}
As expected and discussed in Section \ref{sec:nn_excpected}  the Grid Search (training) of Nearest Neighbor model always conclude with conservative hyper-parameters. With a low \texttt{n\_neighbors} and a low \texttt{radius}. It is very natural since our VSD metric is based on the feature space. 

\section{Discussion}
We can see that for every dataset size, except the eight users one, the collaborative systems perform better. We also noticed that the time required to provide inference by the Nearest Neighbors model increases significantly when increasing the number of users (because the number of tracks also increases) and after a certain amount of users it is not even possible to perform a Grid Search so we picked the best optimal hyper-parameters we got for the hyper-parameters with a smaller user dataset, which are: \texttt{n\_neighbors=3}, \texttt{radius=0}, \texttt{metric=cosine}.

\textbf{8 users} \\
For the smallest dataset size, as we expected during our discussion in Section \ref{sec:nn_excpected}, the Nearest Neighbors model yields the best training results. However, it performs a bit worse than the LMF in generalization capacity when performing recommendation for users it doesn't know. For the MPR metric we refer to the MPR given by the model which gave the best VSD metric and they provide both really close results, but the VAE yields the best MPR score.

\textbf{16 users} \\
For 16 users, the LMF provides better results on the train set but perform worse in generalization capabilities than the Nearest Neighbors. For the MPR the VAE  has still a better score than the LMF.

\textbf{32, 64, 128 users} \\
For higher number of users we noticed that the VAE takes the lead for both training results and generalization capabilities. Focusing on the MPR, we can see that it doesn't necessarily provide the best ordered recommendation, the MPR value gets better for the LMF. The Nearest Neighbors starts to have an enormous amount of items in it's space which leads to significant inference time that isn't compatible to with online recommender system that should be scalable.

We can see that the "test VSD score" for the VAE varies less for different dataset sizes than the LMF or the Nearest Neighbors, leading to more result stability, which is a great advantage to have more confidence when training the model with different amount of users. Although the LMF is the model which has the best training time and that increases the least, this is probably due to the fact that the gradient update is clearly defined and does not rely on algorithmic calculations. In conclusion we can say that adopting a collaborative recommender systems for a small user base isn't necessarily a bad idea and can lead to high quality recommendations.
